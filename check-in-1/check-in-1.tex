\section{Language grammar (EBNF)}

We use EBNF\cite{ISO14977} for the following grammar definition:
\begin{lstlisting}
(* Program *)
program = { declaration }, "render", expression

(* Declarations *)
declaration = "let", identifier, [":", type], "=", expression
            | "event", identifier, ":", type

(* Expressions *)
expression = literal | identifier | lambda | expression expression
            | "let", ident, "=", expression, "in", expression
            | "if" expression, "then", expression, "else", expression
            | expression binop expression
            | "[", expression, {";", expression}, "]"

lambda = "fn", "(", identifier, ":", type, ")", "->", expression

binop = "+" | "-" | "*" | "==" | "<" | "^"

literal = integer | "true" | "false" | string

(* Types *)
type = "Int" | "Bool" | "String" | "UI" | "Signal" type
      | type "->" type | "(" type ")"

(* Identifiers and Primitive Values *)
identifier = ? [a-zA-Z0-9]+ ? ;

integer = ? [0-9]+ ? ;

string = '"', { string_char | escape }, '"'  ;

string_char = ? any Unicode character except " and \ ?  ;

escape = "\", ( '"' | "\" | "n" | "t" )  ;
\end{lstlisting}

\section{Operational semantics}

We define the semantic relations as

\[
  Functions \times Store \times Expr \rightharpoonup Functions \times Store \times UI
\]

\noindent with

\[
  \begin{gathered}
    \phi \in Functions \\
    \sigma \in Store   \\
    e \in Expr
  \end{gathered}
\]

\noindent and $UI = Integer \times String \times Node $. $Node$ still needs to be defined more precisely.

\subsection{Primitives}

For primitives, the $Function$ relation is omitted; hence no $\phi$ in the
following configurations.
\[
  \frac{}
  {\langle \sigma, n\rangle \Downarrow \langle \sigma, n\rangle} \quad\textsc{Int}
\]

\[
  \frac{v = \sigma(x)}
  {\langle \sigma, x\rangle \Downarrow \langle \sigma, v\rangle} \quad\textsc{Var}
\]

\[
	\frac{}{
		\langle \sigma, s \rangle \Downarrow \langle \sigma, v \rangle
	}\quad \textsc{Str}
\]

\subsection{Assignment}

\[
  \frac{
  		\langle \phi, \sigma, e \rangle \Downarrow \langle \phi, \sigma', v \rangle
  	} {
  	\langle \phi, \sigma, x := e\rangle \Downarrow \langle\phi, \sigma'[x \mapsto v]\rangle} \quad\textsc{Assign}
\]

\subsection{Sequence}

\[
  \frac{\langle \phi, \sigma, e_1 \rangle 
  		\Downarrow 
  		\langle \phi, \sigma',v_1\rangle 
  		\qquad 
  		\langle \phi, \sigma', e_2 \rangle 
  		\Downarrow 
  		\langle \phi, \sigma'', v_2 \rangle
  }
  {
  	\langle  \phi, \sigma, e_1; e_2  \rangle 
  	\Downarrow 
  	\langle \phi, \sigma'',v_2\rangle
  } 
  \quad
  \textsc{Seq}
\]

\subsection{Functions \cite[Section~8.1]{hong2023programming}}

Here, $f$ defines \textit{function name}, $x_1, ..., x_n$ are function arguments
and $e_f$ denotes function body.

\subsubsection{Function definition}

\[
  \frac{}{\langle \phi,\operatorname{fn}\ f(x_1,\ldots,x_n)\{e_f\} \rangle \Downarrow \phi[f\mapsto((x_1,\ldots,x_n),e_f)]} \quad\textsc{Def}
\]

\subsubsection{Function call}

\[
  \frac{\begin{gathered}
          \phi(f)
          =          (x_1,\ldots,x_n,e_f) \quad \langle\sigma,e_i\rangle
          \Downarrow \langle\sigma',v_i\rangle \quad \langle\phi, \sigma,e_f[v_1/x_1,\ldots,v_n/x_n]\rangle
          \Downarrow \langle\sigma',v\rangle
        \end{gathered}}{\langle\phi,\sigma,f(e_1,\ldots,e_n)\rangle \Downarrow \langle\phi,\sigma',v\rangle} \quad\textsc{Call}
\]

\section{Reactive semantics and Proofs - TODO}

Relevant papers:  Flapjax\cite{meyerovich:flapjax} and Embedding Dynamic Dataflow in a Call-by-Value Language\cite{10.1007/11693024_20}\\

Following the results these papers, our goal is to implement a \textit{push-driven} dataflow evaluation by maintaining a \textit{reactive dependency graph} $ G $ to manage signal propagation from sources to sinks.\\

Initially our sources will only include events input manually from a CLI. These will be parsed by the OCaml interpreter and, if necessary, a new block of HTML will be output.\\

\subsection{Proofs}
We aim to prove \textbf{Glitch-Freedom}: for any topologically sorted evaluation of $ G $ we have that $ \forall v \in V $ the node $ v $ is evaluated at most once. This guarantees that no intermediate inconsistent states are made visible to the user.
